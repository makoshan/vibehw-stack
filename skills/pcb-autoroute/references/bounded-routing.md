# 有时限的增量布线

适用：密板尾部未连、协商拆线、自动清残线；补充主流程，不替代原生门和制造验收。
来源：2026-10-12 C01 用户提供的运行记录，以及当天只读检查 negotiate.py、boardops.py、gate.sh。日志中的 CPU 饥饿原因未独立复现；以下时间值是起始预算，未做速度基准测试。

## 1. 先跑小样，再开长任务

- 固定输入板、规则、脚本及依赖的哈希；记录主机、KiCad 版本、进程归属。每条分支独立目录、冻结网记录、日志和输出，不能共享可变 frozen.json。
- 从同一份已验基线选一个易网、一个拥挤网做探针；同时记录墙钟时间、进程树 CPU 时间、搜索节点数和原生门结果。没有完整合格候选，不开全网多轮长跑。
- 先跑一条链。另一顺序仅作短预算对照；按“每 CPU 分钟获得的原生门合格改善”决定是否继续，未验的接通计数不能排名。

## 2. 搜索必须有总预算

- 起始预算（可据小样调整并记录）：单网含全部递归与重试，最多 120 CPU 秒或 300 墙钟秒，先到即停；单批最多 15 分钟墙钟时间。原生验收另设有界预算，不算进搜索时间。
- 节点上限、递归深度、重试次数共同受总预算约束。单次 A* 的 max_nodes 不能充当整网超时。
- 超时保留上个合格板，记 TIMEOUT，跳过该网；不得自动把同一参数重跑几小时。结束进程只能用本任务启动并登记的进程树，不宽泛杀进程。
- 一批没有新的合格改善，停止同参数追加轮次。检查最小阻塞区，提出局部换层、换出口或调整布局；改变布局/工艺按原授权范围处理，不为过门擅自降规则。

## 3. 每个候选都是可丢弃事务

[上个合格板] → [独立副本搜索] → [有界清理与重填铜] → [保存并重新加载] → [原生门] → [成功才成为下一网输入]。

- 必须同时对原始保护基线和上个合格板比较。保存焊盘身份、网归属以及原来相连的焊盘集合；不得只比每网簇数或未连总数。相同簇数仍可能断开旧连接。
- 门禁先验证输入：基准必须是可解析且有预期焊盘的 PCB，规则文件单独传入；拒绝把 .kicad_pro 当 .kicad_pcb、空基准或缺失报告。核对原生检查与连接检查的退出码、输入哈希和本次报告时间；错误参数/空板必须作为必失败样本，不能把空集合比较报成旧连接损失 0。
- 检查所有网络及铺铜造成的间接影响，不只检查新增铜所在网。重填铜后检查旧连接保全、原理图一致性、间距/禁布、悬空线孔，以及项目专属保护项。
- 接受条件：新增违规为零、旧连接全部保全、网表无新增差异、项目硬约束未退步，且目标连通确实改善。基线已有例外按项目明确策略锁定，不能用相同违规数量掩盖违规换位。最终验收仍要求项目规定的零未连等全部条件。
- 失败候选留证据但不晋级。不要一边在坏板上继续搜索、一边另起清理脚本追赶修复。
- 原生门耗时若高于搜索，先测清楚瓶颈再调整批量。未经原生门的连续操作只能留在单个隔离候选内，不能标成恢复点。

## 4. 清理要证明不会断网

- “短于线宽”“不足两层接触”只是候选筛选，不是删除依据；短线可能是唯一连接，过孔也可能有明确用途。
- 每次删除/截短先保留快照，重填铜后比较所有受影响的旧焊盘连接，重跑原生检查。变差就撤销；保留测试点、指定地孔等显式保护对象。
- 填铜 → 清线 → 清孔可能互相改变结果；以板内容哈希无变化作为稳定条件，最多 3 轮。达到上限、循环或仍有违规即拒收，不无限清理。
- 回归样本至少覆盖：新增线切断地岛、同簇数却换掉旧连接、短线是唯一桥、悬空孔、清线后新生悬空孔。正常板应通过，故意破坏板必须被挡住。

## 5. 区分没算到和算不出来

- 每 30–60 秒记录一次心跳：当前网/尝试、累计 CPU、墙钟、节点数、最后合格板哈希与门结果。观察区间内整个进程树的 CPU 增量，不能只看等待中的父进程。
- 连续两个采样窗口 CPU 明显偏低（对预期忙碌的单工作进程，可先用 CPU/墙钟 < 0.25 作报警）才调查睡眠、调度、资源竞争或等待 I/O；该比率不能证明具体原因。
- macOS 长任务可用仅随本任务生命周期存在的保持唤醒措施；必须再次测 CPU 兑现率。保持唤醒不等于解除后台调度限制，不用反复改所有进程优先级替代诊断。
- CPU 正常而无合格改善，按搜索预算停止；不要继续把原因归于系统。迁移 Windows/其他主机前查占用，并用同一小样确认运行环境与门结果一致，不承诺 GPU 会加速串行搜索。

## 6. 版本与汇报

- 长任务期间冻结执行代码。修 helper 后的新进程可能读到新版，已有进程通常仍用已加载旧版；不能宣称“后续自动应用”而不记录版本。
- 新脚本先跑回归样本，再从上个合格板另起有界批次；旧任务结果按旧哈希标注，晋级前用当前门重验。不要改别的会话正在使用的脚本。
- 完成由任务退出码和证据文件通知；不堆叠多个等待同一日志的后台循环。
- 只在新合格板、失败原因改变、需要决策时汇报。格式：未连数 / 违规 / 旧连接损失 + 本批 CPU/墙钟 + 下一动作；检查失败的候选明确写“未晋级”。

本文件是执行规则。只有执行器实现并通过上述回归、且完成同输入的前后实测，才能宣称性能优化已生效；修改技能文字本身不代表已加速。
