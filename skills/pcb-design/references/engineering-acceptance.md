# 五项工程验收

适用：整板设计复核、投板前检查、多个源工程合板与自动布线后的验收。根据实际用途控制检查深度，不给个人 demo 增加无关商用认证流程。

## 先冻结对象

查本轮用户指定的目录、交接与并发认领。相似板名不等于同一电路，不能混用其它版本的原理图、规则或装配模型。记录 PCB、工程规则、原理图、接口定义的路径及 SHA256。只在隔离副本填铜、运行会写文件的脚本；完成后核源文件哈希未变。不得为通过检查降低用户规则。

## 检查与结论

| 项目 | 必要输入及检查 | 不能替代的证据 |
|---|---|---|
| 逻辑一致性 | 完整原理图、有效符号引脚电气类型、接口逐脚表、电压域和模式脚；运行 ERC 和全板原理图/PCB 对比 | 从 PCB 反生成的网表或全 passive 符号不能独立证明电路正确；局部源图核对仅覆盖相应引脚 |
| 物理实现 | 原生 DRC 分报未连、其它错误、警告、排除项；填铜后重算；检查关键回路、参考平面与旧连接保全 | 退出码 0 不等于零未连；列出 ignored_checks 和规则排除，零错误仅覆盖启用检查；更低未连数不能抵消旧连接丢失；网名相同不等于物理连通 |
| 制造装配 | 实际板厂叠层和工艺、封装、双面高度、电池/壳体、接口插拔与锁扣、排线触点与卸力、公差 | 缺模型的预览或静态无碰撞不能证明接得上、合得上、可拆装；设计规则未必是已确认板厂能力 |
| 专项性能 | 按需求核电源、时钟、USB/RF、模拟噪声及热；记录计算/仿真/台架原始证据和工况 | DRC、合成数据和网表通过不等于噪声、阻抗或实物通过；无设备就写未实测 |
| 配置放行 | 同一最终版本导出 BOM、坐标、Gerber/钻孔和装配图；记录 ECO、来源、未决项与复核人 | 不拿旧制造包或其他方案模型拼成通过；制造文件通过不等于实物验收或付款授权 |

每项标已验证、失败或未验证，并列证据范围、缺口和下一动作。整板放行不能靠五项取平均；必要项失败或未知就阻塞。未完成工程先输出可执行缺口，不为凑齐报告编造性能结果。

## 四类交付对象绑定同一版本

五项检查回答检查什么；下列四类对象回答交哪版、凭什么判定。可用一份清单和已有报告链接表达，不强制增加四份文档。

| 对象 | 最少记录 |
|---|---|
| 需求与设计基线 | 目标、用户约束、授权范围、设计版本；原理图/PCB/规则/封装/叠层/接口/模型及制造输出的路径和哈希；缺项显式列出 |
| 可执行验收矩阵 | 每项验收的对象、方法/命令、工具版本、工况、合格门槛、负责人和适用阶段；关联需求与证据编号 |
| 版本化验证证据 | 输入版本与哈希、运行时间、工具回执、报告/数据/截图、覆盖范围与未覆盖风险；区分通过、失败、未运行和已失效 |
| 例外与放行结论 | warning/忽略项、工程变更（ECO）、影响范围、补偿检查、残余风险、接受者、授权依据、适用版本/阶段、复验触发条件 |

没有批准记录的忽略项只能叫工具配置或未决项，不能叫已接受例外。独立复核通过只覆盖明确的检查范围，不能自动推导制造或实物放行。

## 修改后的运行闭环

[定义目标、边界、门槛] → [提出候选和修改范围] → [工具执行并验证] → [判定通过、返工或证据失效]

- 用户定义目标、优先级和授权边界；agent 按基线拆任务；脚本/EDA 执行并产生回执；版本记录保存证据及放行范围。模型的解释不充当工具执行结果。
- 每次修改列出受影响的验收项。输入哈希变化时，旧证据先标为不适用于新版本；只有明确依赖未变化且记录了复用依据的项目才可保留，不必盲目重跑无关全套。
- 例如移动连接器，要重核布线、原理图/PCB对应、插拔与壳体开口、线束和贴片坐标；改叠层或规则，要重核相关 DRC、阻抗/回流和制造条件。不能只更新截图延用旧结论。
- 未通过时在既定范围内返工并重跑受影响检查；不可通过放宽门槛、隐藏警告或复用旧证据变成通过。缺资料或无法执行就记录阻塞及下一动作。
- 技术通过后只进入已获授权的下一阶段。沿用用户既有授权，不为每轮可逆修改新增确认；超出授权边界的决定应带具体候选、证据和代价请求用户判断。工具或其他 agent 的通过结论不扩大授权。

交付记录可复用下列最小表头：

`验收项ID | 需求/阶段 | 对象版本与输入哈希 | 方法/工况/门槛 | 负责人 | 证据路径 | 状态/覆盖 | 例外与授权依据 | 修改后复验项`

## 自动化检查的反例

- 连通检查先冻结当前候选的焊盘/铜簇；删除一条已连接信号线必须能查到断开。对铺铜区测试同一区域两个独立铜岛，不能把整个 ZONE 当单一连通节点。仅与很早基线比较会漏掉后续连接的退化。
- 改一个焊盘的网名必须被来源核对拦截。记录比较是否含所有器件/重复焊盘，不把子模块数量说成全板原理图覆盖率。
- SES/其它格式回导要核真正过孔类型枚举、层对、钻孔和铜盘；F.Cu→B.Cu 不是普通通孔类型的充分条件。重载后再次检查。
- 底面焊盘按 IsOnLayer 或实际铜形状判断；不能只看 GetLayer。盘中孔检查用孔与铜盘完整形状，对正反面、同网焊盘同样检查。
- 关键网不能只按最短路径或总未连计数验收；单独检查电源回路、晶体、USB/RF 的路径和回流依据。

## 证据归档

保存工具版本、命令、输入哈希、原始报告、摘要和反例。分开记录本轮重跑与历史证据。检查脚本若返回成功只代表运行完成，摘要仍须明确整板状态。输出里的临时路径要标明不可复用；提供可复现入口。

本地案例来源：原力手环 P37 `five-gate-audit/`（2026-10-26）。五项结构由用户会议照片启发；上述规则是工程操作总结，不当作照片逐字引用，也不作为标准条文。项目数值只留在项目证据，不写死为所有 PCB 的默认规则。

## 人工稿对照与改版复核

**情形**　两个独立绘制的版本要决定哪些做法值得移植。先固定各自的原理图、板、贴片料单和连接器版本。按功能及芯片脚号配对，保留原位号以便回查。

**规则**

1. 对时钟、射频匹配段、稳压去耦、复位、烧录和接口两侧网段，依据芯片脚和器件端点命名。先排除同名异网；原理图与 PCB 同步。保存后同时核对旧→新每个焊盘的名字、网络的完整焊盘集合、原生原理图导出的新名字。只比连通分组会漏掉两边命名不同的错误。
2. 以同一图层、单位、角度容差和长度口径列出异常段。每段记录网络、层、端点、邻铜和改或留的理由。固定必要端点与线宽后尝试折线；新折点若产生间距、急角或回流问题，换走向或保留原线。叠加前后局部图，重铺铜，检查飞线和原生 DRC。全板总线长不作性能评分。
3. 双板接口分别标出从哪一面看、朝向参照、连接器嘴、触点面、1 脚及电源和地。两板在壳内用同一观察坐标，再列逐针映射。原厂上/下双接触座不能单凭板面推定排线铜面朝向。无对应版本装配照片时标出设计走向和待量的折弯余量；实际排线断电逐针测。
4. 人工稿也核原理图与装配 BOM 的值、封装和不贴状态；同一项若有两个值，分别计算它们对门限或工作电流的影响，并查工厂最终选料。

**证据与置信**　一次双板对照中，相同的 20 个接口位置按反序匹配，分压上臂在图与贴片料单中不同。该案例支持逐脚与图料双核；从单块板的线长、角度分布外推性能，置信低。项目具体坐标及测量数据保留在相应项目。
