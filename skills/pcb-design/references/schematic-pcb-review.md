# 外部工具与原理图到PCB交接

适用：用户要求采用外部skill、审查原理图，或从已确认电路继续PCB。复用现有流程，不全量复制第三方skill，也不因可用工具就把局部改图扩成全面投板审查。

## A 工具各做什么

| 工具 | 采用内容 | 不据此声称 |
|---|---|---|
| schematic-design | 图页、模块内部实线、文字避让、封装映射和可编辑交付 | 自动完成PCB布局或器件选型正确 |
| EasyEDA增强 + 已有easyeda-api | 真实引脚坐标、方向、间距、批量放置/引出、清理孤立标签 | 全部标签化就是清晰图；桥在线就是目标文档可编辑 |
| hw-review | 文档版本筛选、完整料号和资料索引、NET拓扑、逐脚证据 | 图/板一致就是手册正确；解析了所有文档就是选中了当前版 |
| kicad-happy | 原生文件结构解析、原理图/PCB交叉分析、按范围追加专项分析 | 自动排版、自动布线、零分析error就可制造 |

优先用现有安装；使用外部副本时记录源URL和commit，先读对应skill及脚本帮助，不执行未经阅读的安装脚本，不复制凭据。工具缺失可用原生EDA完成已授权工作，明确少了哪部分检查。用户只说试用时不改所有客户端配置。

EasyEDA先读health，再确认当前文档类型/版本和只读器件查询；查询失败时排查目标文档，不向未知窗口写入。创建/更新前后读回实体与线段，区分真实器件、网旗和网端口；元件删除不代表关联线/标签已删除。JSON放文件或结构化参数，不内联拼shell。NC、裸露焊盘和机械脚按实际器件定义处理，不盲从示例跳过。

## B kicad-happy可选执行入口

`<kh>`是本次核实的上游`skills/kicad`目录，`<run>`是新的证据目录；运行前以该版本`--help`为准。先查解释器版本：本次PCB分析入口在Python 3.9因联合类型注解报错，Python 3.12可运行。下面`<python>`替换为已核实兼容的Python（不要盲用系统python3）。

```sh
<python> <kh>/scripts/analyze_schematic.py <main.kicad_sch> --output <run>/schematic.json
<python> <kh>/scripts/analyze_pcb.py <board.kicad_pcb> --full --output <run>/pcb.json
<python> <kh>/scripts/cross_analysis.py --schematic <run>/schematic.json --pcb <run>/pcb.json --output <run>/cross.json
```

检查输出schema、器件数、实际网络和输入文件指纹；形状不符先用`--schema`，不反复猜字段。`findings`中的确定性、启发式、datasheet-backed分开读；每条重要告警回到源文件和手册核实，记录真问题/误报/待查证据。源件查不到时记录覆盖缺口，不把空结果当无问题。

没有手册支持的工具结果只能支持一致性或启发式提示。不要把分析告警数与原生ERC/DRC混成一项，也不要为了消除启发式告警改电路。

## C 原理图接入PCB

[冻结电路与约束] → [核符号脚到真实封装焊盘] → [功能组布局和机械接口] → [布线与回流] → [原生检查、专项证据、制造文件]

1. 交接中保留原理图/网表、PCB、规则/排除项、板框叠层、装配变体、接口定义及各自版本。新设计可从零建立；已有工程复用候选，不默认重建或重赋全部网络。
2. 符号脚号→封装pad→厂家对应封装的实脚三者核对；连接器还要核观察方向、触点面、插头和线序。3D外形好看不证明脚映射正确。
3. 原理图局部回路用于布局分组：电源去耦与地回流、反馈、晶体、模拟输入、USB/RF按实际功能与手册放置，不照抄原理图坐标。先核接口插拔、壳体开口、线束卸力、双面高度和安装孔空间。
4. 布线执行已有pcb-autoroute及其基础/专项门禁；保持用户规则和锁定链路；允许在独立候选局部拆线/挪件重布，但最终需恢复既有电气连接。每个候选核旧连接保全、全板未连、其他error、warning和排除项，不以总未连下降抵消旧网络断开。
5. 每次挪连接器、换叠层或修改封装，按影响范围使旧结构/阻抗/DFM等证据失效并复验。下单前按[工程验收](engineering-acceptance.md)绑定同一最终版本，不靠3D、DRC或单一分析器签字。
6. PCB 上做了获批的换脚（芯片转向后整段对调座子脚等），原理图要跟着同步：从定稿板导出逐脚网名（位号.脚号 → 网名），叠到原理图生成脚本的期望网表上；画图按网名找脚，不在脚本里写死脚号。验收用画出来的图按几何重建网表，对 PCB 逐脚比；再故意对调两脚，确认检查能报出来。**证据**：C08B 采集板方案 b 换脚，原力手环仓 `v12/c08b-sch-20261102`（`pcb_pins.py` 导出、`sch.py` 叠加，提交 `25acea2b`），四页 0 错误，独立复核第 2 页 138 组与 PCB 0 不一致。**置信**：低，单工程。

## D 审查深度按任务决定

- **保电路重画**：前后全网表、适用ERC、逐页视觉；用户要求时全板脚网比较。发现原电路疑点单列，不擅自修成不同电路。
- **电路正确性审查**：取得完整料号/封装版本对应的手册、勘误和必要参考设计；每颗IC及相关连接器、晶振、极性/保护器件逐脚追踪到完整网络邻居，不能只写匿名网名。来源记文件、版本、页/章节；额定值、推荐条件、外围取值分别检查。缺资料继续检索并记录具体缺口，未核内容不得判通过。
- **整板/投板审查**：增加PCB交叉核对、原生DRC与规则、装配/制造；按电路和需求执行电源/热、EMC、阻抗/回流、SPICE、Gerber、供应生命周期等适用项。明确不适用、未执行及失败原因。没有有效模型的仿真、统计估算或启发式不提升为实物证据。

手册与原电路冲突时先给证据和影响，只有获得电气变更授权才改。任何第三方“全面工作流”都不自动授权刷机、上电、人体测试、采购付款或运行中的远端任务变更。

## E 已试用的来源

- [kicad-happy](https://github.com/aklofas/kicad-happy)，`2fd9aa0fe2d620f36627d9221e8b1393987ae38e`。2026-10-28原理图解析实跑：C08A 255件/201网，290条结果中179条确定性、111条启发式、0条手册支撑；原生ERC另跑为0/0。仅实跑了该原理图分析入口，未把PCB/EMC/热/仿真入口写成已验证能力。
- [hw-review](https://github.com/ericshang98/hw-review)，`e8178341b6d0f299aa939886a18cdfe3bb845a59`。V4 epro2解析实跑成功，但含多文档和重复位号，需选文档才能使用；不能把原始汇总直接当C08A的BOM。
- 另外两份来源及实际绘图经验见[清晰原理图](schematic-authoring.md)。以上是适配总结，不是上游逐字引用；升级版本后重新核CLI、schema与实际行为。
