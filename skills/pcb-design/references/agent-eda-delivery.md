# 大模型 / agent 参与布板：交付边界

来源：B 站 BV18bnz6EEsS，华中科技大学刘明玉《大模型赋能 PCB 系统设计：从画图到可验证交付》，湾芯展 2026 专题五（2026-10-26 下载、本机 whisper 转写并对照讲义逐页核对；转写有听错处，数字以讲义页为准）。第 7 节的数字来自 Mako 转发的同场另一位讲者的截图，不在该视频内，没有原文核对。

五项验收、四类交付对象、定义→候选→执行→判定闭环已写在 [五项工程验收](engineering-acceptance.md)，这里只补它没有的部分。

## 1 案例：布通不等于交付

- 做法：Codex 里喂原理图、网表、结构图（板框、安装孔、接口位置）→ 调 KiCad 建工程 → 按功能分区摆放（USB 在上、光电传感器在中、逻辑控制在下）→ 脚本跑 DRC 移开干涉 → 关键网预布线找拥塞再调布局 → 导出 DSN 交 Freerouting → SES 回导 → 脚本补双面铺地、修电源连接、优化关键线 → 反复 DRC。几小时出结果。
- 对象：STM32F103C8T6 + PAW3395 鼠标板，51 个器件、39 个网络、196 个焊盘。
- 结果：39/39 网络连通、未连接 0、DRC 0。讲者的结论是这只是「在有限输入下得到一个可验证的候选」，制造性和性能风险评估大量缺失。
- 讲者把这类结果称作演示型：能给你看 demo，到工程应用还有很大距离。价值在于很快把设计推到「可以开始验证」的状态。

## 2 输入边界决定结论边界

模型缺输入时会按经验补默认值（讲者认为大部分幻觉就是这样猜出来的）。工程上的对策是：缺项就列出来，标未验证，不让 agent 自己补。该案例只给了连接关系和几何约束，讲义列出仍缺的四类：

| 类别 | 缺什么 |
|---|---|
| 电气性能 | 协议与速率、阻抗、等长及余量、电流、压降、纹波 |
| 叠层与工艺 | 层数、板材、铜厚、过孔与表面处理 |
| 合规与制造 | 安规、EMC、板厂能力、拼板与焊接工艺 |
| 热与验证 | 功耗、结温、仿真与测试方法、判定准则 |

每类验收标准的来源：逻辑一致性来自原理图、网表、器件库；物理实现来自设计规格书、器件手册、结构约束；制造装配来自板厂和贴片线能力；专项性能来自接口标准、仿真模型、计算书和法规；版本与变更来自项目配置管理。DRC 和连通性只是基础验收。

## 3 任务合同（模型到工具、agent 到 agent）

人和模型之间用自然语言，模型到 EDA 工具、agent 到 agent 之间改用结构化任务合同，至少含：输入版本、引用的约束、允许的动作、验收检查、返回内容。讲义例子：输入版本 `PCB_REV_08`，约束引用 `USB3_DIFF_IMPEDANCE_001`，允许动作为移动无源器件和对指定网络布线，验收检查 `DRC_USB3`、`SI_EYE_MARGIN`，返回变更集、未解决问题和证据引用。讲者的理由：靠一长串上下文加技能包传递，上下文过长会让模型理解变慢并产生歧义。

可检查项：合同没写的动作不执行；返回里没有证据引用的修改不算完成。

## 4 共享设计事实

多个模型和 agent 协作时，只存文件版本不够，对象要细到：器件、引脚、网络、规则有稳定 ID；对象之间有依赖（改哪个会牵动哪些设计和验证）；每次产出带版本和前因后果；修改、冲突、批准、失效都记成状态事件。讲者认为这比传统 PDM 更细，缺了它人、模型、agent 无法稳定协作。

## 5 三种能力的可信度

| 能力 | 讲者判断 | 用法 |
|---|---|---|
| 逻辑（语义理解、需求转换、搭电路） | 通用大模型已够 | 可当主力 |
| 物理（热、SI/PI 预测与判断） | 偏弱，不是要替代仿真 | 结论必须由 EDA 或仿真确认 |
| 优化（布局布线多目标） | 偏弱，希望给出缩小搜索空间的指引 | 候选交工具验证，不当最优解 |

问答里的补充：中低端、器件少的板，验收矩阵简单、公开资料够，通用模型会逐步覆盖；大公司的差距就藏在验收矩阵和私有数据里，会走向本地私有化。

## 6 人的责任与效果评价

- 自动化越强，人的工作越集中到四件事：目标与取舍排序（性能、成本、面积、进度、风险）；模型边界（当前数据和模型是否撑得起这个结论）；例外处理（规则冲突、异常结果、新场景）；授权与责任（哪些修改可自动执行、谁接受最终交付）。模型不承担责任。
- 评价一套系统别只看画得快，看五类：完成度（过了几项验收、遗留哪些风险）、质量（性能余量、返工问题数）、效率（端到端、人工介入次数、失败恢复时间）、成本（模型、工具、人工合计）、泛化（换场景、换板子还行不行）。
