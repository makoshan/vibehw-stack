# vibehw-stack

mstack 管「在 Mako 这里怎么干活」，这层管「怎么把东西做出来」。**唯一真源在 `makoshan/mstack` 的 `skills/vibehw-stack/`**（0.3.0 起），连同下表标「★」的硬件 skill 一起由 mstack `scripts/install.sh` 软链到各 agent 的 skills 目录、每天自动更新；改它们按 mstack §5 走分支 + PR。没标「★」的是上游或自带数据的 skill，留在原处，只在这里点名。

开工顺序：**mstack → vibehw-stack → 当前那一段的 skill**。

## 0. 硬件铁律（和 mstack 第 0 节并列，不重复它）

1. **实物为准。** 下面每一条都是这次亲手踩的，不是格言：
   - 商品图尺寸 ≠ 实测外包络（屏换了 4 次、电池换了 4 次，全是卡尺逼出来的）
   - 模块高度 ≠ 裸屏高度；更小的屏不会自动缩小底层并排尺寸
   - ACK ≠ 用户看到像素；编译通过 ≠ 点亮
   - STEP 有效 + STL 水密 + 两两干涉 0 ≠ 装得进去（要验装入路径、线束、焊点、插头深度）
   - 切片通过 ≠ 打得出来（V22 那个 0.4mm 定位凸台，切片和实打都失败）
   - ERC 0 / DRC 0 ≠ 板能用（那只证明「线接对了、间距够」）
   - 云端训练准确率 ≠ 板上能识别（板端 C++ 要和 Python 回放逐条对齐）
   - AI 效果图不能当尺寸依据
2. **agent 不碰钱。** 打样、贴片、3D 打印外发、面板、元件采购，**全部停在付款前**。付款、发票抬头、收货地址、账号登录由 Mako 自己做。这条没有例外，也不因为「就差最后一步」而松动。
3. **通电前先断电核对。** 供电/背光电流没确认之前禁止点屏；GPIO 不直接扛背光（走恒流）；满电 4.2V 电池不接 3V3；马达跨 VBAT 走低边 MOS + 续流；焊接全程断电，焊完目视 + 万用表通断，最后才上电。锂电那头最后接。
4. **门禁是自己的，平台不会拦你。** 嘉立创 EDA 的 DRC 报了 3 项没解决，照样能导出、照样能下单（aMac1984 那块板就是这么发出去的，HANDOFF 里当场写下「这不代表 DRC 已解决」）。所以每次外发前要有一份**签字的放行审核文件**，写清「过了什么 / 还缺什么 / 谁补 / 哪几条要实物」。

## 1. 七段路：每段派谁，什么时候算过

七段划分沿用 AMAGSTY《从零开始做产品 · 捷径路线图》，门禁和 skill 是我们自己的。

| 段 | 这一段在做什么 | 主力 skill | **门禁（过了才进下一段）** |
|---|---|---|---|
| ① 拆解功能并验证 | 用开发板 + 面包板把需求跑出来 | `vibe-hardware-idea`（查料）· ★`schematik`（找参考接线/模块摘要）· ★`pcb-reference`（开源真板怎么接、选什么料）· `taobao-shopping`（买件）· `investigate`（查故障）· `embedded-ui`（上屏） | 真机上跑通，不是编译通过 |
| ② 制作初期 PCB | 把开发板和模块整合成一块板 | ★`pcb-design`（需求 → 原理图 → 布局 → 打板 → 首板调试，全程的设计纪律）· ★`pcb-high-speed-layout`（高速接口、叠层、时序与回流，按需）· ★`jlc-basic-parts`（选料带 C 号）→ ★`pcb-autoroute`（KiCad 跑到 DRC 0）→ `huaqiu-eda-review`（BOM/ERC/出厂闸）→ ★`jlc-order`（下单）。换工具：★`altium-mcp`（Altium 经 ssh）· `easyeda-api` / `easyeda-eprj3` / `easyeda-pro-format-skill`（嘉立创 EDA） | `ROUTING_ONLY_PASS` **加上**放行审核签字。只有前者是「线连上了」 |
| ③ 设计外观及交互 | 定外观和人机交互 | ★`product-structure-design`（肌电手环结构：分件、卡扣、电极、表带）· ★`hardware-structure-design`（照片/实测 → 参数化零件与装配）· ★`ai-cad-pipeline`（参考图 → STEP+3MF）· `cad`（生成）· `cad-viewer`（审阅）· `step-parts`（买得到的标准件 STEP）· ★`mako-cad-fit`（按实物反馈迭代）· ★`pcb-enclosure-fit`（贴着板子的配合） | 装入路径、线束、接口路径都验过——不是只验体积不干涉 |
| ④ 制作实体并验证 | 确定所有部件的可行性 | `dfam-check`（网格可打印性）· ★`fdm-slicing`（怎么摆怎么打）→ ★`bambu-x2d-slice` / `gcode` / `bambu-labs`（自己打）或 ★`jlc-3dp`（外发树脂）· ★`panel-artwork`（面板）· `sendcutsend` / `dxf`（切割件） | 试片配合过、实装过，不是切片器没报错 |
| ⑤ 整合内外软硬件 | 组合内外，成品 | ★`pcb-photo-annotate`（实物照片标焊盘、判正反面与朝向）· ★`product-render`（板子/整机宣传渲染图）· `handoff`（跨会话）· `codex`（第二意见）· mstack 的车道 | 四态里没有「已实现未验收」压着 |
| ⑥ 宣发 | 讲出去 | `paper-grade-deck` · `pptx` | 「已经是真的 / 还不是真的」两列都写，且不删 |
| ⑦ 小批量制造 | 放量 | ★`jlc-order` · ★`jlc-basic-parts` | 第一批实物验收过 |

### 顺序会走反，代价是真的

这次实际走的是 ① → ③④（36 版外壳）→ ②，而 ② 卡住了。代价当场写进了 HANDOFF：「**在载板打样回来之前不建议再改外壳，V26 先冻住**」——板子最终轮廓没定，外壳每多改一版都可能白改。

**规则：外观可以早做，但「贴着板子的那部分」（开孔、立柱、压条、屏窗、接口位）必须等板子轮廓冻结。** 分不清哪部分贴着板子，就先读 `pcb-enclosure-fit`。

## 2. 硬件上的验证纪律（mstack 那套在实物上的具体形状）

mstack 第 1 节的通用条目不重抄，这里只列硬件特有的：

- **测试替身的形状必须来自实测实物。** 表带连着两版拿理想替身验转动间隙（V26 静止方盒、V27 r2.5 圆柱），测试全绿、实物两次都卡死——真正卡住的是平板的**角**，圆柱身上根本没那个角。没量到实物就把假设写成文件顶部的具名常量，报告里标「假设不是验收」。
- **每条几何检查都要有反向对照。** V36 的电池检查写死「旧 V35 固定片必须与新包络碰撞，V36 才算通过」。只会变绿的检查等于没有检查。
- **判据非单调就不能二分。** 干涉、碰撞、间隙随角度/位置几乎都非单调（表带 −90° 时整个甩到壳外反而是通的）。从已知通过的位姿线性向外扫，粗步 + 细化 + 设上界。
- **量壁厚用中轴脊**，射线采样和球开运算会被圆角/外棱骗出假阳性；每次要拿旧版跑阴性对照。
- **查「接得上」不只查「放得下」。** 体积和 DRC 过了不算数——每个接口要画出排线/导线的实际路径和座子嘴的方向。
- **只重印改动的那个零件**；卡扣先打试片再打整壳；打印件留支撑、清理后再测配合。
- **改一个数会牵动五处。** V35 放不进 5mm 电池，V36 的解法是电池槽底下移 0.3、底壁 1.5→1.2、按钮/开关/固定片/上壳安装座一起上移 0.5，总厚不变。**几何过了不等于强度过了**——减薄后的抗弯没实测，旧的安全系数（1.5mm 底壁 PETG 4.0）不能沿用到新壁厚。
- **照片是最好的实物检查。** 装进壳里那张表盘照片当场看出屏幕左边缘一列杂点（是驱动列偏移）。肉眼看实物容易漏，拍下来放大看不容易漏。
- **核「清单里的坑改了没有」，以清单当前版本逐条对实物。** 情形：被问某份经验 / 检查清单在新设计里落地没有，项目里已有一份落地核对。规则：先比核对文件和清单文件的提交时间；清单在核对之后新增的条目逐条对网表、代码、版图实查；回答写「当前清单第几条 × 实查证据」，不复述旧核对。证据：原力手环 10-24，R01 经验文档 10-22 晚至 10-23 新增「DRDY 去电平转换、测试源脚不接 AVDD、限流电阻在 ESD 前」等 P0，C06 的落地核对是 10-22 下午写的；照它会答「已落地」，实查网表三条都没改，下单前改掉（提交 3303b469）。置信：低（单次）。

## 3. 外发：一次下单要抓下来什么

所有「下单类」skill（`jlc-order` / `jlc-3dp` / `panel-artwork` / `sendcutsend`）共用这个记录格式。下完单当场写，别等。

1. 平台和入口 URL、选项路径（材料/工艺/厚度/数量分别在哪一步选）
2. 上传什么文件、什么格式、打包规则（例：嘉立创 PCB 只传含 Gerber/钻孔的 zip，别把 pos/bom 塞进去）
3. 报价构成 + 当次实价（例：5 片 27.5×37.5 两层 0.8mm，PCB ¥40；经济型 SMT 工程费 ¥50 + 焊点 ¥0.01/点 + 换料费 + 钢网免费 ≈ ¥146 + 元件费）
4. 交期，以及从下单到收货的实际天数
5. **对方回答了什么**——尤其是你逼着问的那几个公差/厚度问题，它决定下一版怎么画
6. 停在哪一步（未付款的单写明「待审核、未付款」）

写进项目 `HANDOFF.md`，同时回写对应 skill。**`panel-artwork` 第 7 节现在就是空的**——面板已下单但这六项一条都没留下，下次补。

## 6. 云与训练段：别去找现成平台，去找现成的件（2026-09-25）

一次把 xiaozhi / 阿里云 ASH / 火山 / 扣子 / TuyaOpen / ESP RainMaker Neo / ThingsBoard / Edge Impulse / Neuton / SSCMA 全查了一遍（vibe-hw `research/ai-hardware-platforms-2026-09-25.md`），规律只有三条：

1. **「AI 硬件平台」分三桶，互不重叠**：语音智能体（ESP32 + 音频 + 云端 ASR/LLM/TTS）· 设备云（管设备 / OTA / 遥测）· 采集训练部署（Edge Impulse 一家独大）。想要「收数据训模型」就别在前两桶里找，那里一家都没有，也没有一家支持 nRF52840。
2. **接各家 Agent 平台只有一个口：MCP。** 扣子、百炼、方舟、xiaozhi-server 全吃 MCP 端点。自己的后端暴露一个 `/mcp`，不为任何一家写 SDK；设备侧只留一条 `POST /events` 的 HTTP 契约。
3. **训练后端默认本地开源件，托管可选。** emlearn（sklearn → C99，MIT）+ TFLM 两条在手表固件 bench 已跑通；Edge Impulse 只做可选托管，白拿它的 Data Acquisition 格式和 mobile-client（BSD）。没有整体开源的 Edge Impulse；最像的 SSCMA 视觉为主且不列 nRF52840。

**回放门禁先拦住的往往是工具默认值，不是模型。** emlearn 0.23 默认把特征量化成 int16，C 桩喂 float 时回放只对 18/60，准确率数字却照样好看。所以训练流水线的第一道检查就是「编译出的 C 和 Python 参考逐窗一致」，并且要有一个故意篡改的必失败样本证明它会红。

**加特征之前先数会话。** 2026-09-25 up_wave：5 场会话、每类约 20 窗，按会话交叉验证下 8 组候选特征、类别加权、加树全都「更差」，连 100 棵树都不如 20 棵——验证本身分不出好坏。这时的结论是「补跨会话的数据」，不是挑一个特征上板；更不能拿独立测试集挑（那就不独立了）。

**门禁不变**：D2 采集质量 / D3 可分性 / D5 板端回放一致，这三道没有任何平台替你做——平台的产品就是这三道门禁，训练只是中间一步。做这一段先读 vibe-hw 的 `EXEC_PLAN_platform_v1.md` 和仓库级 skill `.agents/skills/hw-platform/`。

**升级回路补一行**：这一段的坑写回本文件 §6；接口契约的坑写回项目的 `hw-platform` skill（项目私有，不进这里）。
